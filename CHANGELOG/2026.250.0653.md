# 2026.250.0653 — mcp: explicit 0.0.0.0 listen opt-in inside the container

## Summary

Continuation of PR #4's container-path reconciliation (the plan's §3.8, plan/charly-mcp-systemd-config.md): the charly MCP server's `--listen` default changed to `127.0.0.1` (loopback-only on the host — P3). Inside the container, binding 0.0.0.0 is totally fine and normal — the pod/VM is isolated, and the host only exposes what the operator explicitly publishes. This PR makes the container's listen binding EXPLICIT (`--listen 0.0.0.0:18765`) so the intent is documented in the candy, not implicit in the old default.

- The service exec changes from `charly mcp serve --listen :18765` to `charly mcp serve --listen 0.0.0.0:18765`.
- A comment documents the P3 security model: the host's published port mapping is the security boundary, not the in-venue bind address.
