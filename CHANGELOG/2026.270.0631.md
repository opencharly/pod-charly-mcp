# 2026.270.0631 — fix(ci): bring the candy gate current so it can load layer-charly v2026.269.2324

## Summary

Fix-forward for PR #6: after pinning `layer-charly` to the deterministic
`v2026.269.2324` (#6, merged + tagged `v2026.270.0621`), this repo's `candy` CI
gate went red — the CI-pinned charly (`v2026.241.1121`, max schema
`2026.240.1943`) cannot load the newer `layer-charly` (schema `2026.261.1747`):

```
charly: error: command "validate": validation error: downloading github.com/opencharly/layer-charly:v2026.269.2324:
auto-migrating remote cache .../layer-charly@v2026.269.2324: ... charly.yml:
schema 2026.261.1747 is newer than this charly supports (max 2026.240.1943)
```

The pinned charly is simply too old to consume the modern `layer-charly` tag, so
this brings the repo current — no candy content changes:

- `charly.yml` `version:` `2026.240.1943` → `2026.261.1747` (via `charly migrate`; a
  one-line re-stamp, no shape changes).
- `.github/workflows/deploy.yml`: CI-pinned charly `v2026.241.1121` →
  `v2026.270.0506` (whose `#SchemaVersion` is exactly `2026.261.1747`, matching the
  stamp and remaining consumable by current consumers).

This is the second producer leg after #6; the consumer
`opencharly/distro-cachyos` then pins `pod-charly-mcp` and its direct
`layer-charly` refs.
